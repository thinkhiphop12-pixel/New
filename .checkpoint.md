## Process note — concurrent agents on one branch
Running three subagents in parallel against the same checked-out working
tree (Phase 1 medium-executor, Phase 3 + Phase 15 fast-workers) worked but
produced one commit-boundary bleed: Phase 15's commit picked up Phase 1's
`types.ts`/`storage.ts` edits because both were sitting unstaged in the same
tree when Phase 15 committed. Code correctness wasn't affected and both
commits are pushed, but the "migration in the same commit as the model
change" boundary blurred across two commits instead of one. If parallelizing
again on this branch, prefer agents that touch fully disjoint file sets, or
serialize commit-then-pull between them.
