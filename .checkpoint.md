1. `seasonOutrights` at its first default (60 runs) took 85 seconds — cut to

2. `newsCooldowns` stores absolute week numbers but nothing reset it at

   `tempo:'slow'` + `width:'narrow'` + `tackling:'cautious'` +
   `pressing:'mid'`, each independently suppressing that side's own attack

   losing on. Failed the 2.4–3.2 goals/game band in ~1 in 3 runs (as low as
   2.28) even after an earlier partial mitigation. Fixed by keeping only
   `defLine:'deep'` + `tackling:'cautious'` — confirmed clean across 4
   repeated smoke-test runs post-fix (2.44, 2.53, 2.58, 2.45).

## Phantom-pool duplicate-club bug fixed — pushed tip `dab469a`

Root-caused and fixed the pre-existing `smoke-test-season.ts` failure
flagged at the end of the Phase 11 checkpoint entry below
("ligue_2 pool holds a club that is not dormant"). Real bug, not a smoke
test issue: `processPhantomPool`'s multi-spot inter-league playoff feeder
(Ligue 2's 3rd–5th, via `interPlayoffFeederSpots`) resolved sub-playoffs
by reassigning a `challenger` variable to each sub-playoff's winner, then
unconditionally pushed every extra's *original* id back into the pool —
including whichever extra had just won and become the tracked challenger,
which was separately being promoted or re-pooled under the same id. That
produced a stale duplicate reference sitting in the pool, still tagged
non-dormant. Confirmed with a throwaway repro script that simulated a
season end repeatedly: the duplicate (id 273) showed up in the majority
of runs pre-fix, zero duplicates across 8 runs post-fix. Fixed by
tracking sub-playoff losers separately and only pushing those back to
the pool, never the id that became the surviving challenger.

Verified: `npm run build`/`build:game` clean, `sim-test.ts` in band
(2.48–2.62), `smoke-test-season.ts` prints
`✓ ALL SMOKE TESTS PASSED` again — first clean run since this bug was
uncovered. Confirmed via `git diff` this fix touches only
`seasonProgression.ts`'s `processPhantomPool`, nothing from Phase 11.
