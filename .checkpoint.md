## Phase 0b — LANDED (commit `ee3de2c`)

Storage was a live bug, not just a refactor. Measured before touching it:
a career serializes to 3.96 MB at kickoff and grows to 5.04 MB by the end of
season 3, crossing the ~5 MB localStorage cap. `saveGame` swallowed the
resulting QuotaExceededError, so every career silently stopped persisting in
its third season with no error shown to the player.

Landed:
- `lib/lz.ts` — LZ-String (LZW + bit packing) ported from the reference.
  16.8x on a real save: 5.07 MB -> 0.30 MB, round-trip verified byte-for-byte.
- `lib/idb.ts` — promise wrapper over IndexedDB, one record per slot, resolves
  null when IDB is unavailable so callers can fall back.
- `lib/storage.ts` — payloads in IndexedDB, compressed in a Blob-URL worker so
  a multi-MB write doesn't jank the UI. Slot metadata kept in a small
  localStorage index, so `listSaves()` no longer decompresses and parses three
  full careers to draw the menu. Failures raise `SaveFailedError` instead of
  being discarded. `migrateLegacySaves()` relocates pre-IndexedDB saves and
  absorbs the beforeunload emergency blob.
- `FootballManagerGame.tsx` — persistence debounced to 800ms instead of firing
  on every action; `beforeunload` covers the gap via `emergencySave`.
- `scripts/measure-save.ts` — new harness; tracks save size against the quota
  and asserts the compressed payload round-trips.

Verified at the pushed tip: build, build:game, smoke-test-season (2.84
goals/game, in band), sim-test (league averages 2.47-2.63), measure-save.

Rebased cleanly onto `373b818` (the Phase 3 follow-up pushed concurrently by
another session) — disjoint file sets, no conflicts, re-verified after rebase.

  drill anything.

  half strength (undrilled = blunted, not crippled). Kept out of xgModel's
  imports to avoid a cycle.

### Two findings from Phase 8, both worth reading before touching finances.ts

**Not a bug, initially looked like one:** a "run sensibly" Premier League club
hit an SCR embargo in season 1. Traced to the preview script testing against
`data.clubs.find(c => c.division === 1)`, which resolves to **Liverpool**
specifically (checked `gamedata.json` directly) — one of the highest real wage
bills in the whole dataset. League-wide the SCR spread is healthy (PL median
35%, only 2-3 super-clubs over 70%), which is exactly how real elite-spender
FFP crises look (Barcelona/PSG). Left alone deliberately — recalibrating this
away would make the system worse, not better.

**A real bug, and a second one on top of my own first attempt at fixing it:**
sponsor deals expire on a fixed term, and with no Finances-screen UI to pick a
renewal, an expired slot stayed empty forever — commercial income visibly hit
£0 for two straight seasons in the 5-season preview. Added `autoRenewStaleDeals`
in `tickFinances`. **First attempt was a silent no-op**: I called
`acceptSponsorOffer`/`acceptKitOffer` and discarded their return value — those
two are the codebase's player-action-style functions, they `structuredClone`
the state and `return` a new one (matching every accept/reject function in
`transferMarket.ts`), so calling them without capturing the result does
nothing. Only caught by re-running `finance-preview.ts` after the "fix" and
seeing the exact same zero-commercial seasons recur. Rewritten to mutate `fin`
directly, matching the rest of `tickFinances`'s style. Added a permanent
regression assertion to `smoke-test-season.ts` (6 simulated seasons, commercial
income must never return to zero after the first renewal cycle) so this
specific failure mode can't silently regress again.

**That's five bugs this session now caught only by printing real values, zero
caught by the compiler or a green build.** Treat that ratio as the standing
argument for why every tuned phase needs a `*-preview.ts` before it's trusted,
not an optional nicety.
